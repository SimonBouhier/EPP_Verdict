# ADR-010 : Traçabilité méthodologique (Consensus Meta)
**Date** : 2026-02-15
**Statut** : Actif
**Dépendances** : ADR-005, ADR-007

## Contexte
Une attestation stocke un résultat (score, signature) mais pas la méthodologie qui l'a produit (formule de pondération, version de normalisation, seuils sémantiques).
Sans ces métadonnées, les attestations produites avec des stratégies différentes (ex: avant/après ajout du semantic merge) sont incomparables, et la reproductibilité scientifique est impossible.

## Décision

### Stockage
Ajout d'une colonne `consensus_meta` (JSON/TEXT) dans la table `attestations`.

### Structure
Trois sections obligatoires :
1.  **`methodology`** : Algorithmes utilisés (ex: `hash_exact_v2+semantic_merge_v1`), version normalisation, stratégie pondération.
2.  **`conditions`** : Versions résolues des modèles, poids, séquence des cycles.
3.  **`diagnostics`** : Entropie de Shannon des votes, dispersion sémantique, flag `ambiguity_detected`.

### Intégrité
- **Inclus** dans `portable_json` (payload on-chain).
- **Exclu** du calcul de `claim_hash` (ADR-006). Le hash définit l'identité du claim (quoi), les métadonnées définissent la provenance (comment).

### Migration
Les attestations existantes reçoivent un JSON de migration explicite : `{"methodology": {"consensus_method": "pre-ADR-010"}}`.

## Conséquences
- Obligation de peupler `consensus_meta` à la cristallisation.
- Toute modification de stratégie ESMM doit incrémenter `consensus_method`.
- Augmentation de la taille du payload on-chain (~2KB).
