# ADR-016 : Oracle Géopolitique — Prédictions ancrées sur données de conflit

**Date** : 2026-03-09
**Statut** : Proposé
**Auteur** : Sim (architecte) + Opus (gatekeeper)
**Dépendances** : ADR-012 (chemin déterministe), ADR-010 (consensus_meta), ADR-014 (pattern domain)

## 1. Contexte

Le professeur Jiang Xueqin (Yale, "Predictive History") a formulé en mai 2024
trois prédictions géopolitiques fondées sur des cycles historiques et la théorie
des jeux. Deux sur trois se sont réalisées. Sa méthodologie est exactement le type
de claim que EPP est conçu pour évaluer : opinions structurées + données vérifiables.

La combinaison des deux chemins EPP est la proposition de valeur :
- Chemin épistémique : les LLMs débattent (VERIFY)
- Chemin déterministe : les données ACLED ancrent les faits (ADR-012)

Résultat : une attestation qui dit "cette prédiction est CONTESTED à 0.55 avec
entropy 0.8, ancrée sur 847 événements de conflit vérifiables".

## 2. Décision

### 2.1 — ACLEDAdapter

Fichier : `services/sources/adapters/acled.py`

API ACLED :
- Auth : OAuth2 — POST `acleddata.com/oauth/token` → bearer token 24h
- Credentials : `ACLED_EMAIL` + `ACLED_PASSWORD` (env vars uniquement)
- Endpoint events : `GET /api/acled/read` — événements de conflit
- Endpoint CAST : `GET /api/cast/read` — prédictions 6 périodes
- Format : JSON, pagination `&page=N`, limit 5000/page
- Filtres : country, event_date, event_type, fatalities, actor1, etc.

Deux modes via le champ `mode` du query dict :
- `events` : fetch événements réels (country/date/type)
- `forecast` : fetch prédictions CAST

Normalisation score : `min(1.0, current_events / baseline_12months)`
- `> 2x baseline` → status "escalation"
- `< 0.5x baseline` → status "de-escalation"
- Sinon → status "stable"

### 2.2 — MetrologicalFrame `geopolitical_forecast_v1.0`

Domaine `geopolitical_analysis`, metric `conflict_forecast_assessment`.
Sources autoritaires : acled_events, acled_cast.
`esmm_bypass: false` — les deux chemins coexistent.

### 2.3 — Claims Jiang

8 claims structurées :
- 3 prédictions Jiang (terrain Iran, proxies, Hormuz)
- 2 prédictions résolues (Trump, US-Iran ops) — calibration
- 1 comparaison CAST vs Jiang (forecast delta)
- 2 contrôles (Yemen = conflit actif, Suisse = pas de conflit)

Chaque claim a un `acled_query` optionnel pour le chemin déterministe.

### 2.4 — Script `scenario_jiang.py`

Deux passes par claim :
1. VERIFY épistémique (run_pipeline, comme scenario_6_1)
2. Déterministe ACLED (run_pipeline avec claim_nature=DETERMINISTIC)
3. Comparaison concordance/discordance

DB temporaires par claim. Sortie JSON horodatée.

## 5. Contraintes

- Credentials ACLED en env vars uniquement
- Rate limit : max 10 requêtes par claim, pagination 5000 lignes
- DB temporaires (pas de pollution epp_devnet.db)
- Réseau requis pour ACLED ; si inaccessible, VERIFY seul s'exécute
