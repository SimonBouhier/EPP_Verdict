## Pièges récurrents observés au cours des sessions

1. **`git mv` puis `Edit` puis `git commit`** : si tu ne `git add` pas explicitement après les Edits, le commit ne prend que le rename pur. Toujours faire `git add <file>` (ou `git add -u`) après les Edits, même post-`git mv`. (Bug `4460b54`.)

2. **`ast.parse()` n'est pas `compile()`** : `from __future__ import` mal placé passe `ast.parse` mais plante `compile`. Si tu détectes des Python files mal formés, utiliser `compile(content, filename, 'exec')` pas `ast.parse`. (Bug rencontré dans `add_sys_path_header.py`, fix dans le mode `--repair`.)

3. **Cache CI Lake** : `leanprover/lean-action@v1` calcule sa clé de cache sur 3 fichiers seulement (`lean-toolchain`, `lakefile.toml`, `lake-manifest.json`). Tout changement de structure des sources `.lean` qui ne touche pas ces 3 fichiers laisse la cache valide → restauration incohérente possible. Fix utilisé : invalidation manuelle via UI GitHub Actions.

4. **2 projets Lake dans le repo** était une dette historique. Si tu vois encore un `lakefile.toml` à la racine en plus de `Formal/lakefile.toml`, **stop** — c'est anormal post-`2cfe0be`.

5. **`docs-site/src/content/docs/*` est généré, pas source** : `sync-docs.mjs` les régénère depuis les sources canoniques (`README.md`, `PITCH.md`, `WHITEPAPER.md`, `docs/ARCHITECTURE.md`, `docs/fr/CHANGELOG.md`, `docs/adr/`, `docs/positioning/`). **Modifier le portail = modifier la source + relancer le sync**. Les compteurs hardcodés dans `writeIndexMdx` (sync-docs.mjs lignes ~310-312) sont une exception — édition directe.

6. **anchorpy 0.21.0 inutilisé mais installé** plante pytest depuis le venv (plugin auto-loaded). Si tu vois `ModuleNotFoundError: No module named 'pytest_xprocess'`, c'est anchorpy. Désinstaller. Le code n'a aucun import effectif d'anchorpy (4 mentions = commentaires).
