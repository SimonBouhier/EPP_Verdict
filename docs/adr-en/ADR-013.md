# ADR-013: Persistent Graph & Epistemic Cache-Hit

**Date**: 2026-03-01
**Status**: Applied
**Dependencies**: ADR-010 (consensus_meta), ADR-012 (deterministic_source TTL)
**Axioms invoked**: 3 (regression-cut transparency), 4 (local computation, on-chain proof)

---

## Context

Each `run_pipeline()` starts from scratch even if the claim has been deliberated recently.
`data/epp.db` accumulates valid attestations that are never reused. The cost of a full deliberation
(~150s, 3+ models) is prohibitive for claims that are stable on a 7-day horizon.
The deterministic path (ADR-012) has its own TTL via `is_snapshot_fresh()` — the ADR-013 cache applies to the epistemic path only.

---

## Decision

Add a cache-hit in `run_pipeline()` **before** the ESMM cycles.
`_check_cache()` queries `get_attestations_by_question()` with the exact question
(the `question` field of the `attestations` table — never the `subject` extracted by ESMM),
filters by TTL and minimum tier, and returns a `PipelineResult(from_cache=True)`
if a fresh and qualified attestation exists. On error: normal pipeline (non-blocking).

**Configuration**: `config.yaml` `cache` section (`enabled`, `ttl_hours=168`, `min_tier_for_cache="proposition"`).
**Disable**: `use_cache=False` in `PipelineConfig` — mandatory for benchmarks.

---

## Consequences

### What changes

| Component | Modification |
| :--- | :--- |
| `services/esmm/pipeline.py` | `PipelineConfig` +`cache_ttl_hours` (168h), +`use_cache` (True); `PipelineResult` +`from_cache`, +`cache_hit_hash`; `run_pipeline()` +cache-hit before ESMM; `_check_cache()` new (read-only) |
| `database/engine.py` | +`get_attestations_by_question()` — `WHERE question = ?`, sorted by `timestamp DESC` |
| `config.yaml` | +section `cache` (`enabled`, `ttl_hours`, `min_tier_for_cache`) |
| `demos/scenario_6_full_pipeline.py` | `use_cache=False` in `run_epistemic_claim()` and `run_rwa_claim()` |
| `tests/test_pipeline_cache.py` | CREATED — 3 RED-GREEN-FIX tests |

### What does not change

- On-chain `EpistemicAttestation` structure (462 bytes) — unchanged
- ESMM cycles — unchanged (the cache bypass is transparent)
- ADR-012 deterministic path — its own TTL via `is_snapshot_fresh()`
- CLI — `get_db()` already resolves the persistent `data/epp.db`
- `from_cache=True`: logged, not sent on-chain

### Invariants

- `_check_cache()` **never** modifies the database — read-only
- On exception in `_check_cache()` → `logger.warning` + normal pipeline (never blocking)
- `use_cache=False` in every benchmark scenario
- The cache does **not** apply to the deterministic path (ADR-012) — that path has its own TTL

### Risks

| Risk | Mitigation |
| :--- | :--- |
| Cache returns stale attestation | Configurable TTL (168h default). `min_tier_for_cache` blocks `sandbox` |
| `_check_cache()` blocks the pipeline | `except Exception → return None` — never blocking |
| Benchmark polluted by the cache | `use_cache=False` mandatory in `scenario_6` |
| Lookup by question doesn't match | Exact `question` stored in DB on every run — `get_attestations_by_question()` does `WHERE question = ?` |
