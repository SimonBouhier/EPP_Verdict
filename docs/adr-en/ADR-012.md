# ADR-012: RWA source integration — Deterministic / Epistemic bifurcation
**Date**: 2026-02-25
**Status**: Proposed
**Dependencies**: ADR-005, ADR-006, ADR-010, ADR-011-v2
**Axioms invoked**: 3 (regression-cut transparency), 4 (local computation, on-chain proof)

---

## Context

Integration of institutional RWA sources (sanctions, carbon registries) exposes a class of claims absent from the current model: **deterministic claims**. Entity X is or is not on the OFAC list. VCU credit #N is or is not issued and not retired. These facts have a single authoritative answer — submitting such a claim to the ESMM pipeline injects false uncertainty into an objective fact and degrades performance with no value added.

The current code does not distinguish a claim's epistemic nature (deliberative vs deterministic). `claim_type` in VERIFY mode approaches the right granularity but does not integrate the notion of an authoritative external source. The `source_anchor` field (32 bytes) already exists on-chain in `EpistemicAttestation` — it is underused.

---

## Decision

### Explicit bifurcation in `ESMMRunConfig`

```python
class ClaimNature(str, Enum):
    EPISTEMIC     = "epistemic"      # Full ESMM pipeline (default)
    DETERMINISTIC = "deterministic"  # Authoritative source lookup, ESMM bypass
```

`ESMMRunConfig` accepts two optional fields: `claim_nature` (default `EPISTEMIC`) and `source_anchor_spec`. If `claim_nature = DETERMINISTIC` without `source_anchor_spec` → init error. The choice is **declared by the caller**, never inferred automatically (Axiom 3).

### New module `services/esmm/source_anchor_builder.py`

Single responsibility: query an external source, validate the response, and produce a `SourceAnchorResult`.

```python
@dataclass
class SourceAnchorSpec:
    source_id: str           # "ofac_sdn" | "opensanctions" | "verra_vcs" | "eu_cfsp"
    frame_id: str            # Associated metrological frame
    query: Dict[str, Any]    # Query parameters
    max_age_hours: int = 24  # TTL — beyond this, re-fetch is mandatory
    min_sources: int = 1     # Concordant sources required for "verified" tier

@dataclass
class SourceAnchorResult:
    source_id: str
    raw_response: Dict[str, Any]       # Full JSON — stored off-chain (SQLite)
    normalized_result: Dict[str, Any]  # {"status": "clear"|"match", "score": float}
    source_anchor: str                 # SHA-256(canonical raw_response) → on-chain
    fetched_at: float
    source_version: str                # e.g.: "OFAC-2026-02-25"
    is_fresh: bool
```

**The `source_anchor` is the SHA-256 of `raw_response` serialized as canonical JSON (sorted keys, compact).** This value is what goes on-chain. The full `raw_response` stays in SQLite (new `source_anchor_snapshots` table).

### Four adapters in `services/sources/adapters/` [Renamed from `services/rwa/` — ADR-014 §2.1]

Common interface `SourceAdapter` (fetch + normalize + get_source_version). Implementations:

| Adapter | Source | Endpoint |
|:---|:---|:---|
| `OpenSanctionsAdapter` | OpenSanctions (yente) | POST `/match` |
| `OfacAdapter` | OFAC SDN (US Treasury) | POST `/screening` |
| `EuCfspAdapter` | EU CFSP / Sanctions.network | GET `/sanctions` |
| `VerraVcsAdapter` | Verra VCS Registry | GET `/projects/{id}` + `/credits/{serial}` |

The adapters are pure HTTP wrappers without business logic.

### Three new `MetrologicalFrame`

**`compliance_sanctions_v1.0`** — domain `regulatory_compliance`, metric `sanctions_status`. Key parameters: `authoritative_sources: [OFAC_SDN, EU_CFSP, UN, opensanctions]`, `match_score_threshold: 0.85`, `snapshot_ttl_hours: 24`, `esmm_bypass: true`. Tier assigned by `required_sources` (1 → `proposition`, 2 concordant → `validated`, 3 + score ≥ 0.95 → `verified`).

**`carbon_credits_vcs_v1.0`** — domain `environmental_assets`, metric `carbon_credit_validity`. Two explicit layers: L1 deterministic (serial lookup, `esmm_bypass: true`) and L2 epistemic optional (methodological soundness, `esmm_bypass: false`, off by default). L1 and L2 produce two attestations linked by `previous_hash` (ADR-006). L2 cannot exist without a validated L1.

**`rwa_identity_v1.0`** — generalist frame for combining multiple sources. If the deterministic source score is ambiguous (< configurable threshold), optionally triggers an ESMM layer for contextual analysis. The only frame where the two paths chain automatically.

### Impact on `consensus_meta` (ADR-010)

Every deterministic attestation carries a `source_anchor_meta` section in `consensus_meta`:

```json
{
  "methodology": {
    "consensus_method": "deterministic_source_v1",
    "esmm_invoked": false
  },
  "source_anchor_meta": {
    "source_id": "ofac_sdn",
    "source_version": "OFAC-2026-02-25",
    "fetched_at": 1740470701,
    "is_fresh": true,
    "snapshot_id": "uuid"
  },
  "diagnostics": {
    "sources_checked": 2,
    "concordant_sources": 2,
    "result": "clear"
  }
}
```

Validation at crystallization: absence of this block on a `deterministic_source` attestation → rejection.

### New SQL table

```sql
CREATE TABLE IF NOT EXISTS source_anchor_snapshots (
    snapshot_id    TEXT PRIMARY KEY,
    source_id      TEXT NOT NULL,
    source_version TEXT NOT NULL,
    query_hash     TEXT NOT NULL,   -- SHA-256(canonical query JSON)
    raw_response   TEXT NOT NULL,   -- Full JSON
    source_anchor  TEXT NOT NULL,   -- SHA-256(raw_response) → on-chain
    fetched_at     REAL NOT NULL,
    frame_id       TEXT NOT NULL,
    UNIQUE (source_id, query_hash, source_version)
);
```

## Consequences

### What changes

| Component | Modification |
|:---|:---|
| `services/esmm/source_anchor_builder.py` | **NEW** |
| `services/sources/adapters/` | **NEW directory** — 4 adapters [Renamed from `services/rwa/` — ADR-014 §2.1] |
| `services/solana/metrological_frame.py` | +3 frames |
| `services/esmm/orchestrator.py` | `ESMMRunConfig` +`claim_nature` +`source_anchor_spec`, bifurcation at the start of `execute_cycles()` |
| `services/esmm/attestation.py` | `crystallize()`: handles `attestation_mode = "deterministic_source"` in `consensus_meta` |
| `database/schema.sql` | +`source_anchor_snapshots` table |
| `database/engine.py` | +`store_source_anchor_snapshot()`, `get_snapshot_by_anchor()`, `is_snapshot_fresh()` |
| `config.yaml` | +section `sources.adapters` (TTL, credentials via env vars, enable/disable per adapter) [Renamed from `rwa.sources` — ADR-014 §2.1] |
| `cli/epp_cli.py` | +command `epp verify-rwa --source --entity --frame` |

### What does not change

- On-chain `EpistemicAttestation` structure (462 bytes) — `source_anchor` already exists
- Claim hash (ADR-006) — immutable
- ESMM ASSESS/CHALLENGE/ADJUDICATE cycles — unchanged for the epistemic path
- `run_pipeline()` interface — transparent if `claim_nature` not specified

### Risks

| Risk | Mitigation |
|:---|:---|
| Exposed API credentials | Env vars only, never in versioned config.yaml |
| Stale snapshot | Conservative 24h TTL. SQLite cache avoids needless re-fetches |
| Verra VCS API schema instability | Adapter versioning (`VerraVcsAdapterV1`). Bump forces re-attestation |
| Deterministic / epistemic confusion by a consumer | `consensus_meta.methodology.esmm_invoked` readable off-chain in SQLite |

### Open questions — COMMUNITY_DECISION_REQUIRED

**Q1** — Differentiated fees for deterministic vs epistemic? Payment vector (SOL, USDC, EPP token)?

**Q2** — Who guarantees the integrity of `raw_response` before hashing? TEE or ZKP out of ADR-012 scope — to be addressed before mainnet.

**Q3** — On-chain validity duration of a deterministic attestation. A credit attested as "not retired" at time T may not be at T+30d. What mechanism triggers revalidation?

---

## Recommended implementation order

1. `source_anchor_builder.py` + `OpenSanctionsAdapter` (zero credentials, open-source, immediately testable)
2. Frame `compliance_sanctions_v1.0` + RED-GREEN-FIX bypass tests
3. `ESMMRunConfig.claim_nature` + orchestrator bifurcation
4. Table `source_anchor_snapshots` + migration
5. `OfacAdapter` + `EuCfspAdapter`
6. `VerraVcsAdapter` L1 only
7. VCS frame + L1/L2 chaining once L1 is stable
