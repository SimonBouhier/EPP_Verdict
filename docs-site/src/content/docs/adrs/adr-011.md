## 1. Problem

### 1.1 — The symptom

Three models extract triplets denoting the same fact with different vocabularies. The `ConsensusEngine` treats them as distinct facts and filters them for lack of agreement.

Live example observed (Ollama, mistral + llama3.1 + deepseek-r1):

| Real fact | Mistral | Llama 3.1 | Deepseek |
|:---|:---|:---|:---|
| Solana uses Proof of History | `solana / uses / proof of history` | `solana / relies_on / PoH` | `solana network / implements / proof-of-history` |

Consensus produces three triplets each at 33% agreement. The threshold `min_agreement=0.5` eliminates them all. Consensus is zero, although the three models agree on the substance.

### 1.2 — Existing mechanisms and their limits

**Layer 0 — `normalize_triplet()`**: static dictionary of synonyms (9 entity entries, 10 relation groups, 7 substitutions). Does not cover non-pre-encoded domain terms. Does not scale.

**Layer 2 — `_semantic_merge()`**: post-hoc clustering by cosine > 0.85 via embedding provider. Requires a configured embedding provider (not guaranteed locally). Operates after the vote — a triplet eliminated in Pass 1 never reaches Pass 2. Mathematical heuristic, not semantic resolution.

### 1.3 — Why the cross-model prompt approach fails (v1 → v2)

The first version of this ADR (v1) proposed a RECONCILE phase where models would see each other's outputs and propose an alignment table by vote.

The Moltbook study (Lin, Li et al., arXiv:2602.14299, February 2026) invalidates this approach. This large-scale study on a society of autonomous LLM agents demonstrates that:

1. **Deep inertia**: LLM agents maintain their semantic trajectory regardless of what they are shown. They "interact without listening". Showing other models' triplets to a model does not guarantee it will propose intelligent alignment.

2. **Interaction without influence**: the volume of interaction and density of exchange are insufficient indicators of social convergence. Models communicate with each other without transmitting information or modifying behavior.

3. **Convergence mechanisms must be explicit**: "Scaling interaction is not the same as scaling governance." Convergence cannot emerge from an invitation to socialize — it requires structural governance mechanisms.

These results render the three v1 options (bare terms, anonymized triplets, grouped triplets) insufficient. All rely on the ability of models to listen to and react to other models' outputs — exactly what Moltbook shows they don't do.

### 1.4 — The structural gap reformulated

The problem is not that the models don't communicate enough (the v1 hypothesis). The problem is that **the semantic identity of a term does not reside in the term itself, but in its conceptual neighborhood**. "PoH" and "proof of history" are the same concept, not because a dictionary says so, nor because a model declares it, but because both terms **occupy the same place in the structure of knowledge**.

Reconciliation must be structural, not linguistic.

## 2. Decision

### 2.1 — Principle: Semantic Fingerprinting

Each model produces, for each term it has extracted, a **semantic micro-graph** — a small neighborhood of 3 to 5 directly related concepts. This micro-graph constitutes the **semantic fingerprint** of the term according to that model.

A **deterministic algorithm** (not an LLM) then compares the fingerprints. Two terms whose neighborhoods overlap above a threshold are recognized as designating the same entity. Arbitration is mathematical, reproducible, and independent of any model.

Separation of responsibilities:

| Role | Executor | Justification |
|:---|:---|:---|
| Describe the meaning of a term | The LLM (each describes **its own** terms) | Egocentric work — LLMs excel at expressing their knowledge |
| Compare descriptions | A deterministic algorithm | Structural matching — reproducible, no inertia, no bias |
| Decide merge or distinction | The algorithm, by threshold | Regression-cut transparency (Axiom 3) — threshold is explicit and versioned |

**Fundamental property**: no model sees another model's outputs. Epistemic contamination is **structurally impossible**, not merely discouraged by the prompt.

### 2.2 — Fundamental constraint: zero epistemic contamination

Identical to v1 — this constraint is preserved and reinforced.

**What Semantic Fingerprinting modifies:**
- Entity identifiers: `"PoH"` → `"proof of history"` (or shared parent node)
- Relation identifiers: `"implements"` → `"uses"`
- Form groupings: `"solana network"` and `"solana"` are recognized as the same entity

**What Semantic Fingerprinting NEVER modifies:**
- Confidence of a triplet
- Attribution to source model
- Agreement ratio
- Truth decision

If a model M extracted `(S, R, O)` with confidence `c`, and fingerprinting recognizes `S ≡ S'`, then the triplet becomes `(S', R, O)` with confidence `c`, still attributed to M.

### 2.3 — Three-phase architecture

#### Phase 1 — EXPAND: micro-graph generation

After triplet extraction (STEP 2 in `triplet_extractor.py`), each model receives a prompt asking it to describe its own terms:

```
You extracted the following terms: {terms_list}

For EACH term, provide 3-5 directly related concepts with the relationship type.
Use ONLY these relationship types: is_a, part_of, used_by, produces, related_to, invented_by

Output JSON:
{
  "term_name": [
    ["relationship", "related_concept"],
    ...
  ]
}
```

**Each model receives only its own terms.** Mistral does not know Llama extracted "proof of history". It only describes "PoH" as it understands it.

Result: a `Dict[str, Dict[str, List[Tuple[str, str]]]]` — for each model, for each term, a list of (relation, neighbor concept).

Example:

```
Mistral → "PoH" → [(used_by, solana), (provides, timestamp_ordering),
                    (is_a, consensus_component), (invented_by, anatoly_yakovenko)]

Llama →   "proof of history" → [(used_by, solana), (enables, transaction_ordering),
                                 (is_a, consensus_mechanism), (related_to, vdf)]

Deepseek → "proof-of-history" → [(part_of, solana), (produces, cryptographic_timestamps),
                                   (is_a, consensus_protocol)]
```

#### Phase 2 — MATCH: Hybrid Entity Resolution

The arbiter is a deterministic algorithm. It does not just compare words; it compares **semantic positions in the vector space**, giving more importance to **Strong Anchors** (Named Entities).

##### Step 2a — Strong Anchor identification

Before comparison, each neighbor in the micro-graph is classified:

- **Strong Anchor** (`weight = 2.0`): Named Entity (detected via uppercase / lightweight NER) **OR** term already present in the global knowledge graph.
  E.g.: `"Solana"`, `"Anatoly Yakovenko"`.

- **Weak Descriptor** (`weight = 1.0`): generic term or adjective.
  E.g.: `"speed"`, `"mechanism"`, `"scalable"`.

##### Step 2b — Cascade neighbor matching (The Waterfall Match)

To compare a neighbor v₁ (model A) with a neighbor v₂ (model B), the algorithm uses a cascade of increasing precision:

**1. Lexical Match (Fast Path):**
- `normalize_triplet()` (Layer 0)
- Jaro-Winkler distance
- Condition: if score > 0.9 → **MATCH** (100%)

**2. Vector Match (Semantic Path):**
- If lexical fails, vectorize v₁ and v₂ via the system's `EmbeddingProvider` (`nomic-embed-text` or similar)
- Compute Cosine Similarity
- Condition: if score > 0.85 → **MATCH** (100%)
- Justification: enables matching `"High Throughput"` and `"Fast Speed"` that Jaro-Winkler misses entirely

##### Step 2c — Weighted overlap score

The score between two terms T_A and T_B is no longer a simple ratio, but a weighted sum of matched neighbors:

$$Score(T_A, T_B) = \frac{\sum (Weights_{matched})}{\min(\sum Weights_A, \sum Weights_B)}$$

Example: if `"Solana"` (Anchor, weight 2) is shared, the score climbs much faster than if `"fast"` (Weak, weight 1) is shared.

##### Step 2d — Transitive Clustering (Connected Components)

Instead of merging pair-by-pair (which creates inconsistencies A≈B, B≈C, A≠C), we build a **temporary similarity graph**:

- **Nodes** = terms from all models
- **Edges** = pairs with Overlap Score ≥ `merge_threshold`
- **Action**: extract the **Connected Components**

Result: if Mistral links `"PoH"` to `"Solana"`, and Llama links `"Proof of History"` to `"Solana"`, transitivity merges them mathematically, even if their other neighbors differ.

#### Phase 3 — APPLY: Injection with Alignment Table

The resulting cluster (the connected component) defines the Alignment Table:

- **Canonical selection**: in each cluster, the longest or most frequent term is elected "Canonical Representative".
- **Injection**: the table is passed to the `ConsensusEngine` before hashing.

**Final flow:**

```
1. EXPAND  (LLMs isolated)                    → Micro-graphs
2. MATCH   (Hybrid Cascade + Clustering)       → Synonym clusters
3. ALIGN                                       → Mapping table {"PoH": "Proof of History", ...}
4. HASH                                        → SHA-256 on canonical forms
5. MERGE   (L2)                                → Residual catch-up
```

### 2.4 — Pipeline insertion point

The v2 architecture integrates the correction discovered by Claude Code in the v1 plan: consensus is coupled to per-cycle extraction, and raw `model_triplets` are not exposed to the orchestrator.

The solution is identical: two-pass approach.

```
ESMM cycles (divergent → debate → meta)
    │
    ├── Each cycle: extraction + per-cycle consensus (diagnostics, logs)
    │   └── The orchestrator ALSO accumulates raw model_triplets
    │
    ▼
EXPAND (each model describes its own terms — micro-graphs)
    │
    ▼
MATCH (deterministic algorithm compares neighborhoods)
    │   ├── Direct merges → alignment_table
    │   ├── Sub-nodes → alignment_table + aggregation nodes
    │   └── Distinctions → no action
    │
    ▼
FINAL CONSENSUS (cross-cycle, with alignment_table)
    │   └── Replaces per-cycle _collected_triplets
    │
    ▼
finalize_run() → crystallization → attestation
```

The insertion point is in `orchestrator.run()`, between `execute_cycles()` and `finalize_run()`. RECONCILE is an internal orchestrator concern — the pipeline does not need to know it exists.

### 2.5 — Interaction with existing mechanisms

**`normalize_triplet()` remains active** (Layer 0). It covers known static synonyms before fingerprinting.

**`_semantic_merge()` remains active** (Layer 2). It covers cases that fingerprinting does not detect (neighborhoods too different but embeddings close).

**The three layers are complementary and ordered:**

| Layer | Mechanism | Type | Coverage | Cost |
|:---|:---|:---|:---|:---|
| 0 | `normalize_triplet()` | Static dictionary | Known synonyms | O(1) |
| 1 | **Semantic Fingerprinting** (new) | Neighborhood comparison | Domain synonyms, contextual variants | O(n² × k) |
| 2 | `_semantic_merge()` | Embedding clustering | Residual vector similarity | O(n² × d) |

The application order is strict: L0 → L1 → hash → L2. Each layer catches up what the previous one missed. If L1 is disabled or times out, L0 and L2 ensure minimum coverage (current behavior).

### 2.6 — Cross-cycle consensus

The introduction of Semantic Fingerprinting creates an intentional architectural side effect: the final consensus is recomputed on **all** the accumulated `model_triplets` from **all** cycles, with the alignment table applied.

Today, each cycle has its own independent consensus. A triplet extracted by Mistral in DIVERGENT #1 and an equivalent triplet extracted by Llama in DEBATE #2 are never compared — they are counted separately in distinct consensuses.

Cross-cycle consensus fixes this. It is a logical consequence of fingerprinting: if micro-graphs reveal that "PoH" (cycle 1) and "proof of history" (cycle 2) are the same concept, the final consensus must count them together.

Per-cycle consensuses remain for diagnostics and logs. The cross-cycle consensus replaces them for crystallization.

### 2.7 — Graph enrichment (Axiom 2)

Major difference with v1: micro-graphs **are** structured knowledge.

In v1, the alignment table was ephemeral — discarded after the run. In v2, micro-graphs have intrinsic value:

- Common neighbors across multiple models are high-confidence relations
- Sub-nodes capture facets of a concept that each model perceives differently
- Micro-graphs that confirm themselves across runs become candidates for injection into the main graph

Injection is not automatic — it follows the same consensus threshold as normal triplets. But the reconciliation mechanism **produces** knowledge instead of consuming it. The graph survives and grows (Axiom 2).

### 2.9 — Degraded mode and configuration

```yaml
esmm:
  fingerprint:
    enabled: true
    max_neighbors: 5           # Neighbors requested per term
    min_neighbors: 3           # Minimum for a valid fingerprint
    merge_threshold: 0.6       # Overlap for merging
    subnode_threshold: 0.3     # Overlap for sub-node
    matching_algorithm: "jaro_winkler"  # or "ngram", "exact_only"
    timeout_seconds: 60        # Global EXPAND + MATCH timeout
    min_unique_terms: 5        # Below this, fingerprinting skipped
    inject_micro_graphs: false # Phase 1: no. Enable post-validation.
```

If fingerprinting is disabled, times out, or if the number of unique terms is insufficient, the pipeline continues with L0 + L2 (current behavior). `consensus_meta.reconciliation.method` reports `"skipped"` with the reason.

### What does not change

- `run_pipeline()` signature — transparent for callers
- `claim_hash` (ADR-006) — claim identity is independent of intermediate vocabulary
- Confidence tiers (ADR-005) — epistemic judgment is preserved
- On-chain format — the attestation carries the canonical forms post-reconciliation
- `normalize_triplet()` and `_semantic_merge()` — existing layers preserved

### Risks

| Risk | Probability | Mitigation |
|:---|:---|:---|
| Micro-graphs are noisy (incorrect neighbors) | Medium | The overlap vote filters non-shared neighbors. An incorrect neighbor in a single model does not pollute the score. |
| Computational cost (n² comparisons) | Low for MVP | n = number of unique terms per run (~20-50). O(n²) ≈ 400-2500 comparisons, each trivial. Potentially an issue only at scale. |
| False synonyms via accidentally similar neighborhoods | Low | High `merge_threshold` (0.6 = majority of neighbors in common). Possible review of merges via `consensus_meta`. |
| False distinctions via too-different neighborhoods | Medium | L2 (`_semantic_merge`) catches these. The system has three chances to detect a synonymy. |
| The textual matching algorithm (Jaro-Winkler) introduces false positives between neighbors | Low | Tunable. In strict mode: `exact_only`. Textual matching is applied to neighbors, not to the terms themselves — an error on a neighbor degrades the score but does not cause a false merge. |
| The EXPAND prompt is ignored or poorly filled by a model | Medium | Structural validation of JSON. An invalid micro-graph is ignored — that model's term remains without a fingerprint and is reconciled only by L0 and L2. |

### Open questions — COMMUNITY_DECISION_REQUIRED

**Q1 — Injecting micro-graphs into the main graph.** Disabled by default (`inject_micro_graphs: false`). When should recurring micro-graphs (confirmed across multiple runs) become permanent relations? What recurrence threshold? This creates a synonym dictionary auto-built by observed structural convergence.

**Q2 — Sub-node granularity.** A sub-node enriches the graph but adds complexity. Should they be created on the first run or wait for multi-run confirmation? The answer depends on the domain: in blockchain (stable vocabulary), sub-nodes are rare; in an emerging domain (e.g. AI regulation), facets of the same concept frequently diverge.

**Q3 — Adaptive thresholds.** The `merge_threshold` and `subnode_threshold` thresholds are fixed. Should they adapt to the domain or to the number of models? With 3 models, an overlap of 0.6 means a minimum of 2 shared neighbors out of 3. With 10 models, the same threshold is much more permissive.

**Q4 — Existing-graph feedback.** If the graph already contains `"proof of history"` as a concept, should the MATCH algorithm use it as an additional reference neighbor? This would favor convergence toward established forms but introduce a bias toward history.

## 5. Implementation notes

### 5.1 — Divergences from the initial plan

The original plan (§3) provided for a single `fingerprint.py` module. The final implementation uses 4 modules (`fingerprint_config.py`, `fingerprint_expand.py`, `fingerprint_match.py`, `fingerprint_apply.py`) per the 200-line max/module constraint.

The EXPAND prompt is in `fingerprint_expand.py` (not `cycle_prompts.py`) because EXPAND is not a `CycleType` — it's a post-cycle reconciliation phase.

### 5.2 — Post-audit corrections (C1-C5, 18 February 2026)

The initial implementation contained 5 bugs identified by audit:

| Bug | Severity | Correction |
|:---|:---|:---|
| C1 — Cross-module import of private functions | Blocker | 3 self-contained functions in `fingerprint_match.py` |
| C2 — `.rotator` attribute does not exist | Blocker | `.model_rotator` (real name in `cycle_manager.py`) |
| C3 — `batch_sequential_providers` sends ALL questions to EACH provider | Critical | Per-provider loop: `provider_ids=[provider_id]` |
| C4 — Incorrect questions format | Fragile | `questions=[[{"role": "user", "content": prompt}]]` |
| C5 — `apply_alignment_to_triplets` only handles dicts | Fragile | Normalization to dicts at accumulation point + `hasattr` net |

### 5.4 — Shared relation vocabulary (Q5)

The initial implementation defined synonym relation groups independently in `consensus_engine.py` (10 groups) and `fingerprint_match.py` (6 groups), with concrete divergences (`relies_on` → DEPENDS_ON in consensus but → `uses` in fingerprinting). Resolved by extracting a shared `relation_vocabulary.py` module (11 groups, superset). The `produces ∈ CAUSES` conflict is a compatibility choice (ADR-006 hash stability). The vocabularies of `prompts.py` (LLM-facing) and `relation_normalizer.py` (DB-backed) remain separate. Deployment via `use_legacy_relation_groups` flag in `config.yaml`.

19 dedicated tests in `test_relation_vocabulary.py`: 9 module tests + 10 CI gate hash-stability (ADR-006).
