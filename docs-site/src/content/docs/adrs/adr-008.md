---
title: "ADR-008 : Strategie d'authentification du submitter Solana"
description: "Le pipeline EPP soumet des attestations epistemiques on-chain via un keypair"
---
**Date** : 2026-02-12
**Statut** : Actif

## Contexte
Le pipeline EPP soumet des attestations epistemiques on-chain via un keypair
Solana local. Le submitter signe chaque transaction — son pubkey est stockee
dans l'attestation comme preuve d'origine.

## Decision

### Keypair management
- Le keypair est charge depuis un fichier JSON non chiffre
  (`~/.config/solana/id.json` par defaut, configurable via `keypair_path`).
- Seule la pubkey est loggee (`AUDIT[A10-021]`). La cle privee n'est JAMAIS
  exposee dans les logs, configs, ou reponses API.
- En CI/devnet, utiliser un keypair dedie au pipeline (pas le keypair personnel).

### Signature et verification
- Anchor impose que le submitter soit `Signer` sur l'instruction
  `submit_attestation` (`lib.rs:124`). Seul le detenteur du keypair peut soumettre.
- Le champ `submitter` dans l'attestation on-chain est la pubkey du signataire,
  verifie par le runtime Solana.
- Pas de delegation : un keypair = un submitter. Pour plusieurs submitters,
  deployer plusieurs keypairs.

### Restrictions
- **Devnet/localnet uniquement** : `validate_cluster()` interdit mainnet
  (`config.py`). Le enum `SolanaCluster` n'a pas de valeur MAINNET.
- **Pas de rate limiting on-chain** : le rate limiting est cote pipeline
  (un run ESMM produit N attestations, pas plus). Le programme Anchor ne
  limite pas le debit par submitter.
- **Challenge** : tout holder de keypair peut challenger une attestation
  existante. Le challenge cree une nouvelle attestation liee a la PDA challengee.

### Risques acceptes
- `AUDIT[A10-009]` : keypair en JSON non chiffre. Acceptable pour devnet.
  Pour mainnet (futur), exiger un HSM ou un wallet hardware.
- `AUDIT[A10-008]` : le guard devnet est cote client, pas on-chain. Un attaquant
  peut contourner via RPC direct. Acceptable car le programme est deploye sur
  devnet uniquement.

## Consequences
- Ne PAS deployer sur mainnet sans migration vers keypair chiffre/HSM.
- Ne PAS ajouter de delegation sans un nouvel ADR.
- Documenter le keypair dedie dans le README deploiement.
