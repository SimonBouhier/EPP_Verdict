**Date** : 2026-03-01
**Statut** : Appliqué
**Dépendances** : ADR-010 (consensus_meta), ADR-012 (deterministic_source TTL)
**Axiomes mobilisés** : 3 (transparence des coupures), 4 (computation locale, preuve on-chain)

---

## Contexte

Chaque `run_pipeline()` repart à zéro même si le claim a déjà été délibéré récemment.
`data/epp.db` accumule des attestations valides non réutilisées. Le coût d'une délibération
complète (~150s, 3+ modèles) est prohibitif pour des claims stables à horizon de 7 jours.
Le chemin déterministe (ADR-012) a son propre TTL via `is_snapshot_fresh()` — le cache
ADR-013 s'applique au chemin épistémique uniquement.

---

## Décision

Ajouter un cache-hit dans `run_pipeline()` **avant** les cycles ESMM.
`_check_cache()` interroge `get_attestations_by_question()` avec la question exacte
(champ `question` de la table `attestations` — jamais le `subject` extrait par l'ESMM),
filtre par TTL et tier minimum, et retourne un `PipelineResult(from_cache=True)`
si une attestation fraîche et qualifiée existe. En cas d'erreur : pipeline normal (non bloquant).

**Configuration** : `config.yaml` section `cache` (enabled, ttl_hours=168, min_tier_for_cache="proposition").
**Désactivation** : `use_cache=False` dans `PipelineConfig` — obligatoire pour les benchmarks.

---

## Conséquences

### Ce qui change

| Composant | Modification |
| :--- | :--- |
| `services/esmm/pipeline.py` | `PipelineConfig` +`cache_ttl_hours` (168h), +`use_cache` (True) ; `PipelineResult` +`from_cache`, +`cache_hit_hash` ; `run_pipeline()` +cache-hit avant ESMM ; `_check_cache()` nouveau (lecture seule) |
| `database/engine.py` | +`get_attestations_by_question()` — `WHERE question = ?`, tri par timestamp DESC |
| `config.yaml` | +section `cache` (enabled, ttl_hours, min_tier_for_cache) |
| `demos/scenario_6_full_pipeline.py` | `use_cache=False` dans `run_epistemic_claim()` et `run_rwa_claim()` |
| `tests/test_pipeline_cache.py` | CRÉÉ — 3 tests RED-GREEN-FIX |

### Ce qui ne change pas

- Structure on-chain `EpistemicAttestation` (462 bytes) — inchangée
- Cycles ESMM — inchangés (le cache bypass est transparent)
- Chemin déterministe ADR-012 — son propre TTL via `is_snapshot_fresh()`
- CLI — `get_db()` résout déjà `data/epp.db` persistant
- `from_cache=True` : loggué, non envoyé on-chain

### Invariants

- `_check_cache()` ne modifie **jamais** la base — lecture seule
- En cas d'exception dans `_check_cache()` → `logger.warning` + pipeline normal (jamais bloquant)
- `use_cache=False` dans tous les scénarios de benchmark
- Le cache ne s'applique **pas** au chemin déterministe (ADR-012) — celui-ci a son propre TTL

### Risques

| Risque | Mitigation |
| :--- | :--- |
| Cache retourne attestation périmée | TTL configurable (168h défaut). `min_tier_for_cache` bloque sandbox |
| `_check_cache()` bloque le pipeline | `except Exception → return None` — jamais bloquant |
| Benchmark pollué par le cache | `use_cache=False` obligatoire dans `scenario_6` |
| Lookup par question ne matche pas | `question` exact stocké en DB lors de chaque run — `get_attestations_by_question()` fait `WHERE question = ?` |
