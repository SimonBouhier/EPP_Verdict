## 1. Context

### 1.1 — The problem: every run starts from scratch

Today, the ESMM pipeline treats every claim as if the system had no memory. When three LLMs evaluate "Donald Trump won the 2024 US presidential election", they produce CONTESTED at 0.43 — their knowledge cutoff blinds them. When Wikidata confirms the fact at 0.85 via the deterministic path, both attestations coexist on-chain. But the knowledge acquired by the deterministic source never benefits the LLMs.

The next run on the same claim, or on a related claim, restarts from the same ignorance. The graph accumulates verified knowledge that no one consumes.

### 1.2 — The founding observation

The `jiang_20260311_082057.json` run illustrates the waste:

| Path | Score | Time |
|:---|:---|:---|
| VERIFY (3 LLMs) | 0.43 CONTESTED | ~104s |
| DETERMINISTIC (Wikidata) | 0.85 found | ~2s |

If the LLMs had had access to the Wikidata result in their context, the verdict would have been significantly different. Not because the answer is forced — but because the verified information is available, and not providing it is a design choice, not a technical constraint.

### 1.3 — The concept: Epistemic Flywheel

A **flywheel** is a mechanism that accumulates energy at each rotation and returns it to the next cycle. The Epistemic Flywheel applies this principle to the EPP knowledge graph:

1. **Accumulation** — Each deterministic attestation enriches the graph with verified, timestamped, hashed knowledge.
2. **Restitution** — Before LLM deliberation, the pipeline consults the graph for existing deterministic attestations on the same `claim_hash`.
3. **Injection** — The results found are injected into the LLMs' system prompt as verified factual context.
4. **Amplification** — The LLMs deliberate with a stronger factual base, producing more accurate verdicts, which in turn enrich the graph.

The graph becomes smarter at every cycle without retraining any model.

## 2. Decision

### 2.1 — Principle: the graph feeds the pipeline that feeds the graph

Before the ESMM cycle loop (ASSESS → CHALLENGE → ADJUDICATE in VERIFY mode), the pipeline performs a lookup in the local database for existing deterministic attestations carrying the same `claim_hash`.

If deterministic attestations exist, their results are formatted and injected into the system prompt as a `[VERIFIED DATA]` section.

The LLMs remain free to contest the data — the injection is informative, not prescriptive. The final verdict can diverge from the deterministic source, and that divergence is itself a signal (Axiom 5).

### 2.2 — Lookup of existing anchors

```python
async def _lookup_existing_anchors(
    claim_hash: str,
    db: "DatabasePool",
) -> list[dict]:
    """
    Searches existing deterministic attestations for a claim_hash.

    Returns:
        List of dicts {source_id, score, status, results, fetched_at, source_version}
        sorted by date (most recent first).
    """
    query = """
        SELECT subject, predicate, object, consensus_score,
               consensus_meta, created_at
        FROM attestations
        WHERE claim_hash = ?
          AND json_extract(consensus_meta, '$.methodology.claim_nature') = 'deterministic'
        ORDER BY created_at DESC
        LIMIT 5
    """
    rows = await db.fetch_all(query, (claim_hash,))

    anchors = []
    for row in rows:
        meta = json.loads(row["consensus_meta"]) if isinstance(row["consensus_meta"], str) else row["consensus_meta"]
        source_meta = meta.get("source_anchor_meta", {})
        anchors.append({
            "source_id": source_meta.get("source_id", "unknown"),
            "score": row["consensus_score"],
            "status": source_meta.get("normalized", {}).get("status", "unknown"),
            "results": source_meta.get("normalized", {}).get("results", []),
            "fetched_at": source_meta.get("fetched_at", row["created_at"]),
            "source_version": source_meta.get("source_version", "unknown"),
        })

    return anchors
```

### 2.3 — Injection into the system prompt

```python
def _format_anchor_context(anchors: list[dict]) -> str:
    """
    Formats deterministic anchors for injection into the LLM prompt.

    The format is informative, not prescriptive. The LLMs are free
    to contest the data — divergence is the signal.
    """
    if not anchors:
        return ""

    lines = ["[VERIFIED DATA — from deterministic sources, for context]"]
    for a in anchors:
        results_str = ""
        if a["results"]:
            # Extract readable values (e.g.: "winnerLabel: Donald Trump")
            for r in a["results"][:3]:  # Max 3 results
                results_str += ", ".join(f"{k}: {v}" for k, v in r.items() if k != "item")

        lines.append(
            f"- Source: {a['source_id']} | Status: {a['status']} | "
            f"Score: {a['score']} | Data: {results_str} | "
            f"Fetched: {a['fetched_at']} | Version: {a['source_version']}"
        )

    lines.append("[END VERIFIED DATA — you may contest these findings if your analysis disagrees]")
    return "\n".join(lines)
```

### 2.4 — Injection point in pipeline.py

In `run_pipeline()`, **after** the `claim_hash` computation and **before** the cycle loop:

```python
# --- Flywheel: lookup existing deterministic anchors (ADR-018) ---
anchors = await _lookup_existing_anchors(claim_hash, db)
anchor_context = _format_anchor_context(anchors)

if anchor_context:
    logger.info(f"[Flywheel] Found {len(anchors)} deterministic anchor(s) for claim_hash={claim_hash[:12]}...")
    # Inject into system prompt for all subsequent cycles
    flywheel_injection = anchor_context
else:
    flywheel_injection = ""
```

The `flywheel_injection` is concatenated to the system prompt of every cycle (ASSESS, CHALLENGE, ADJUDICATE). It appears as factual context, not as instruction.

### 2.5 — Traceability in consensus_meta

The flywheel injection is documented in `consensus_meta` to ensure reproducibility (Axiom 3):

```python
consensus_meta["methodology"]["flywheel"] = {
    "enabled": True,
    "anchors_found": len(anchors),
    "sources_injected": [a["source_id"] for a in anchors],
    "injection_timestamp": datetime.now(timezone.utc).isoformat(),
}
```

If no anchor is found:

```python
consensus_meta["methodology"]["flywheel"] = {
    "enabled": True,
    "anchors_found": 0,
    "sources_injected": [],
}
```

This explicitly distinguishes:
- **Attestation without flywheel** (historical runs): `flywheel` key absent
- **Attestation with flywheel, no anchors**: `anchors_found: 0`
- **Attestation with flywheel, anchors injected**: `anchors_found: N, sources_injected: [...]`

Two attestations produced with and without flywheel on the same claim are **explicitly non-comparable** (Axiom 3). `consensus_meta` documents it.

## 4. What does not change

- **Deterministic path (ADR-012)** — unchanged. The flywheel consumes deterministic attestations, it does not modify them.
- **Claim hash (ADR-006)** — immutable. The flywheel searches by existing `claim_hash`.
- **On-chain structure** — no modification. PDAs remain identical.
- **Confidence tiers (ADR-005)** — unchanged. The flywheel can improve the score, but the tier is computed with the same rules.
- **EXPLORE mode** — not concerned. The flywheel only activates in VERIFY mode (factual claims).

## 6. Guardrails

### 6.1 — Injection is informative, not prescriptive

The prompt explicitly says: *"you may contest these findings if your analysis disagrees."* An LLM that contests a deterministic source produces a valuable second-order signal — it can indicate a stale source, a wrong QID, or a claim whose ground truth has changed.

### 6.2 — No self-referential loop

The flywheel only re-injects **deterministic** attestations (`claim_nature = "deterministic"`). It never re-injects VERIFY attestations into the prompt of another VERIFY. No model sees its own previous verdict — only data from external sources.

### 6.3 — Anchor freshness

The most recent anchor is prioritized (`ORDER BY created_at DESC`). If a deterministic source is updated (e.g., Wikidata corrected), the new anchor takes over. Old anchors stay in the DB but are not injected if a more recent version exists.

### 6.4 — Disable

`config.yaml: flywheel.enabled: false` disables the mechanism. Runs without flywheel remain possible and comparable to historical runs.

## 7. Risks

| Risk | Probability | Mitigation |
|:---|:---|:---|
| Bad anchor propagated (wrong QID, corrupt source) | Low | LLMs can contest. The MAX_CONFIDENCE of sources (0.85 Wikidata) prevents the score from reaching 1.0. LLM vs anchor divergence is logged. |
| Confirmation bias: LLMs follow the anchor blindly | Medium | The prompt explicitly states the right to contest. `vote_entropy` measures whether LLMs really deliberate or conform. An entropy < 0.5 with anchor injected would signal excessive conformism. |
| Prompt overload with too many anchors | Low | Capped at 5 anchors, 3 results per anchor. Estimated token budget: ~200 tokens max. |
| Confusion between runs with and without flywheel | Medium | Explicit traceability in `consensus_meta` (§2.5). Axiom 3 respected. |

## 8. Link with ADR-017 (Clusters)

In a multi-cluster network, the flywheel becomes even more powerful:

- **Cluster A** produces a deterministic attestation via Wikidata.
- **Cluster B**, querying the same claim with different models, finds Cluster A's anchor on-chain via `getProgramAccounts` + `claim_hash` filter.
- Cluster B injects the anchor into its own LLMs.
- The entire network benefits from every deterministic attestation produced by any cluster.

The flywheel is intra-cluster in Phase 1 (local DB). It becomes inter-cluster in Phase 2 (on-chain lookup). The code is the same — only the lookup source changes (local SQLite → Solana `getProgramAccounts`).

## 10. Success metric

The flywheel is considered functional if:

- **JIANG-RESOLVED-01** moves from CONTESTED (~0.43) to SUPPORTED (>0.70) with flywheel enabled
- **`vote_entropy` stays > 0.7** (the LLMs still deliberate, no blind conformism)
- **`consensus_meta` correctly documents** the injection (`sources_injected` non-empty)
- **Tests pass** without regression (baseline 801 maintained)
